Getting started

1. Add OpenUtility to Discord. 2. Sign in to the web dashboard with Discord. 3. Select a server you can manage. 4. Open Server Configuration or Security Center and configure the systems you need.

OpenUtility works best when its role is high enough to manage the roles it needs to protect or moderate, and when View Audit Log is enabled for security features.

Web Dashboard

The dashboard is the central control plane for your server. Use the server selector to choose a manageable guild, then configure Overview, Server Configuration, Security Center, Moderation, Logging, Welcome and Embed Builder.

The dashboard should reflect real server configuration rather than demo values. Security telemetry such as live threat events depends on the bot publishing that data to the backend.

🛡️ Security Center

OpenUtility's Security Center combines Anti-Nuke, threat scoring, burst detection, raid protection, permission escalation monitoring, protected resources, trusted actors, Panic Mode and recovery snapshots.

Threat Scoring

Security events add threat points to an actor or server security state. Scores decay over time so isolated legitimate actions do not permanently create a high threat state.

Burst Detection

Rapid destructive actions such as multiple channel or role changes can be detected within short windows instead of relying only on long-term counts.

Raid Protection

Monitor abnormal join bursts using configurable thresholds and windows. Depending on configuration, a detected raid can raise the threat level or activate Panic Mode.

Permission Escalation

Monitor dangerous permission grants and role changes, including Administrator, Manage Guild, Manage Roles, Manage Channels, moderation permissions, webhook management and Mention Everyone.

Protected Resources

Mark important channels and roles as protected. Changes or deletion of protected resources can produce high-severity security events.

Trusted Users & Roles

Trusted users and roles can be excluded from configured Anti-Nuke protections. Review this list carefully and keep it limited to accounts you trust.

Panic Mode

Panic Mode provides an emergency response state. It can be activated manually or automatically when configured critical security conditions are reached.

Recovery Snapshots

Snapshots store server structure information such as roles, channels, hierarchy and permission overwrites. Recovery should be treated as a safety feature and tested on a non-production server first.

Security Simulation

Use simulation/testing to validate detection pipelines without intentionally punishing users or modifying the server. Simulation is intended for configuration verification.

Security protection is not a guarantee against every Discord attack. Keep Discord permissions minimal, protect the bot token, maintain trusted-user lists carefully and test recovery before relying on it during an incident.

👋 Welcome System

The Welcome Studio provides customizable join and leave experiences.

  • Custom welcome and leave messages
  • Rich embeds with title, description, color, images, thumbnails and footer
  • Join DMs
  • Automatic roles
  • Dynamic variables such as {user}, {user.mention}, {user.name}, {server}, {membercount} and {avatar}
  • Live preview and test configuration

Keep welcome channels visible to new members and ensure the bot has Send Messages and Embed Links where required.

🗂️ Moderation & Cases

OpenUtility records important moderation actions as cases so staff can review a member's history and understand why an action occurred.

WarnRecord a warning with target, moderator and reason.
TimeoutTemporarily restrict a member with a recorded duration and reason.
Kick / BanRemove a member and record the moderation event.
AutoMod CaseRecord automated violations and the rule that triggered them.

Use cases as an audit trail. Keep reasons factual and avoid putting sensitive information into public log channels.

📋 Advanced Logging

Configure separate channels for server, member, moderation, message, role, channel, voice and security activity where supported.

Security events should be routed to a restricted staff channel. Avoid exposing moderation details or sensitive audit information to ordinary members.

🎨 Embed Builder

Create custom Discord embeds with a live preview, content, author/style, media, fields, JSON editing and send options. The preview is designed to represent the actual embed that will be sent.

When using webhooks, verify the destination and webhook permissions before sending.

🔐 Permissions & Security

Discord remains the authority for guild permissions. OpenUtility also checks dashboard access and server permissions on the backend.

Security features may require View Audit Log. Moderation features can require Ban Members, Kick Members, Moderate Members or other relevant permissions. Anti-Nuke and recovery features may require additional management permissions. Place the OpenUtility role above roles it must manage.

Never share the bot token. Use least-privilege permissions where possible and review dashboard access regularly.

🔧 Troubleshooting

Server is missing

Confirm you can manage the server in Discord, OpenUtility has been invited, and refresh the dashboard.

Bot appears offline

Check the OpenUtility status page and the bot hosting logs. A Discord gateway or hosting issue can prevent commands from responding.

Security events are not detected

Check View Audit Log, the bot's role position, enabled protection rules and trusted/protected resource configuration.

AutoMod does not act

Check that the rule is enabled, the bot can moderate the target member, and the configured action is supported by the bot's permissions.

Welcome message does not send

Verify the configured channel, Send Messages, Embed Links and any required role permissions. Use the dashboard preview/test tools where available.

Dashboard keeps asking for login

Clear cookies for the OpenUtility site, sign in again and verify the production OAuth configuration.

Dashboard or API is unavailable

Check the OpenUtility status page.
